# 执行边界联合验收（R04–R09）

本文补充跨 Tier 调用、GC／根／补丁生命周期、目标平台 ABI 三组验收要求，细化现有架构的正确性边界。它记录应验证的行为，不表示相关实现或测试已经通过；不预先选定双入口槽、寄存器物理分区或另一种 GC 算法。

## 适用范围与阶段归属

| 阶段 | 本文对应职责 |
|---|---|
| R03 | 提供已有的类型、值／引用、闭包、异常、借用／效果事实及依赖关系；完整热更协议仍由 R09 负责。 |
| R04 | 明确调用、根描述和补丁交换契约，以及目标 ABI 的参数／返回值规则。 |
| R05 / R06 | 实现 VM 帧与根、桥接边界、移动更新、宿主隔离及加载／回收生命周期。 |
| R07 | 实现目标 ABI lowering、跨 Tier 桥接和 AOT GC 元数据的真实生成、链接与消费。 |
| R08 | 以独立预期结果和对应 VM/AOT 差分验证可观察行为。 |
| R09 | 验证三阶段切换、并发发布、失败处理和旧版本回收。 |

按当前启用的能力切片验收，缺少实现或执行证据的项目保持待完成，不因本文件出现而视为通过，也不把完整 R09 设为无关 R03 切片的前置。先使用锁定工具链在 Windows 本机验证；其他目标的同类矩阵按既有 R13 平台计划扩展。

<a id="tier-calls"></a>

## 1. 跨 Tier 调用

### 调用与发布契约

- 明确每种调用入口的签名、调用约定及参数／返回值传递方式。原生调用方可达的入口在切换前后保持约定一致；字节码阶段由适配入口完成 Native ABI 与类型化 VM 帧之间的转换。
- 桥接明确 FunctionId、闭包环境和执行上下文的来源与寿命；同签名的不同函数仍须被正确区分。按签名复用适配代码不代替函数身份传递。
- 调用过程中需要保活的参数、返回值和临时引用，在可触发 GC 的操作前进入有效根集合；正常返回、受管异常和请求终止均按对应语义完成运行时清理。受管异常不穿越 Zig/C ABI。
- 每次调用观察到的入口、tier、代码版本及所需元数据属于同一次完整发布。单入口、双入口或描述符间接层由实现选择，但分别写入多个字段不构成一致性证明；已取得旧入口的调用和旧活动帧在退出前仍受生命周期保护。

### 验收场景

1. 对支持的签名覆盖 Native→Native、Native→VM、VM→Native、VM→VM，检查参数、返回值、状态变化和失败结果。用例包含整数／浮点混合、寄存器外参数、结构体参数／返回、受管引用或 ABI 句柄，以及捕获环境；尚未支持的类型明确保持待完成。
2. 同签名多函数、递归、嵌套调用及闭包在三阶段切换后仍访问正确函数和环境。旧帧继续完成，新调用按发布协议进入有效版本，不要求替换正在执行的帧。
3. 在桥接可分配点触发 GC，验证临时根、返回值和异常载荷仍可用；验证受管异常、请求终止与宿主边界各自的处理和清理结果。
4. 调用与更新交错、重复／乱序更新、链接／加载／发布失败时，不观察到混合版本的入口和元数据，保留已验证的可用版本。代码与 GC 元数据回收同时满足下一组的生命周期要求。

<a id="gc-lifetime"></a>

## 2. GC、根与补丁生命周期

### 根与地址契约

- 根描述能够区分活动引用、可空引用、联合类型的活动载荷与纯标量位；初始化、覆盖、控制流传参、异常传输及帧退出的根状态有明确规则。非活动载荷和未初始化位不得被误作引用。
- GC 只在帧和根状态满足协议的 safepoint 观察它们。引用槽分区、固定根表和按 safepoint 的根描述均可按实际表示选择；分区不代替失活槽处理、临时根或引用重定位。
- 区分原生稳定缓冲区、受管对象内部地址和缓冲区内的受管引用。跨 safepoint 的地址须有稳定性或重定位保障；Span 的容器结构稳定与对象保活／元素引用更新分别证明，不统一禁止所有 Span 跨 safepoint，也不从原生分配推定没有 GC 职责。
- AOT GC 元数据按锁定工具链、目标对象格式及实际加载地址解析和注册，不假定不同平台使用相同节名或布局。代码对调用方可见前，其所需元数据必须可用；旧代码的调用、活动帧及并发扫描对元数据的使用均结束后，才可注销并卸载相关资源。

### 验收场景

1. VM 与 AOT 的对应引用能力分别覆盖移动前后访问、别名、可空／联合载荷、闭包环境和异常传播。确认对象确实移动且值／身份仍正确，不能仅以执行过 collect 代替重定位验证。
2. 在分配、桥接和控制流传参的适用边界检查根的完整性；引用被覆盖、异常退出或请求终止后按既定寿命释放。反复调用及循环在规定内存预算下验证根保留量，避免失活槽无限积累。
3. 验证合法稳定借用在 GC 后仍有效，已定义的稳定／重定位路径须有正例；缺少这些保障的受管内部地址跨 safepoint 时静态拒绝，不以运行时兜底代替适用的静态借用证明。
4. R06/R07 在扩大 AOT 引用能力前，用当前 Windows 工具链完成最小真实链路：生成对象、链接并加载库、注册元数据、触发移动收集、继续执行，同时核对该执行路径所需的栈展开／回溯信息。R09 在此基础上验证旧帧与新版本并存、扫描与回收交错，最后注销元数据和卸载旧库。
5. 元数据损坏、注册或加载失败时，候选不能成为可调用版本；失败清理和正常回收均不得移除仍被使用的代码／根信息。既有可用版本继续满足其执行契约。

<a id="target-abi"></a>

## 3. 目标平台 ABI 一致性

### 布局与调用契约

- DataLayout 负责类型大小、对齐和字段 offset；调用约定另行明确参数分类、寄存器／栈传递、聚合类型拆分或间接传递、隐藏返回地址及适用扩展规则。不能由布局相同推定调用兼容。
- 外部边界继续使用目标平台 C ABI，契约身份绑定目标及实际调用规则。Windows 与其他目标可采用不同的 ABI lowering，同一目标的 producer／consumer 必须一致。
- 值参数与显式借用参数分别保留其语义。不能把所有值类型机械改成指针后声称仍然零复制；采用间接传递时，明确临时存储、别名、可变性、所有权及返回值存储的责任。

### 验收场景

1. 用真实 Zig/C 调用方与被调用方，双向调用 tsfg 生成代码；同时覆盖直接调用和适用的函数指针／热更桥接入口。检查字段值、返回值和可观察副作用，不把未定义的 padding 字节当作语言结果。
2. 对当前支持的 ABI 类型覆盖整数位宽与符号扩展、规范 bool、浮点、混合参数、寄存器用尽后的栈传参，以及不同大小／对齐的结构体参数和返回。聚合类型用例至少区分小整数大小结构体、12／16 字节聚合和需要返回存储的较大聚合；向量类型仅在实际支持时加入。
3. 用独立 Zig/C 探针核对 size、align、offset、参数接收与返回存储；测试调用方和被调用方遵守源语言的值／借用语义。VM/AOT 一致仅作为补充，不能替代独立预期结果。
4. 签名、目标或 ABI 身份不匹配时在发布／调用前按正式边界拒绝，并验证没有进入错误调用。新增目标复用同一语义场景，分别核对其本机 ABI，不要求不同目标的布局和传参字节相同。

## 验收记录与复用

在对应任务已有摘要中记录覆盖的能力／调用方向、源码与工具链身份、目标及配置、实际结果和未完成项，引用已有合格日志。输入与覆盖未变的结果可复用；新增类型、调用规则或生命周期路径只补验受影响项。本文不要求额外证据包，也不以文档检查代替真实执行验收。
