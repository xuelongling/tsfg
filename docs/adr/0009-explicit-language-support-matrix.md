# 用显式支持矩阵界定 tsfg 语言

tsfg 以官方 TypeScript 前端的 fork 为基础，普通语言规则直接沿用固定基线，只为特殊且必需的架构需求客制化。R01 Q2 的显式支持矩阵记录实际 lowering/执行能力及差异：待实现与架构禁止项分别记录，前端升级不会自动证明后端已支持新增能力；它不要求逐项重新规定 TS 语言。记录及路线修正日期：2026-09-09。

Q13 曾要求完全遵循 TypeScript 语法；Q14 允许在实际冲突处优先保证 tsfg 表达质量；Q19 经研究后已确认：普通 TS 声明、类型和已有 API 优先，其余必要的编译期声明意图优先使用少量 @ 标记，注释主要用于文档。先复用 TS 合法位置，函数位置仅在真实需求证明必要时扩展；不预建通用注解设施或新增关键字。代价是必要扩展仍需维护上游工具差异和规范/诊断，但避免将语言语义统一放进注释后额外承担语义注释保留及自定义标签工具约定。未扩展区域保持 TypeScript 行为，不支持 JavaScript 程序的边界不变。

此前将此选择表述为“未经重新规定的 TS 语义一律拒绝”过度扩大了范围，已按用户最新指导撤回。当前取舍是复用上游规则/源码/测试以减少重复维护，同时记录必要 tsfg 差异并对当前不能 lowering 的能力如实诊断；语义引用已明确但实现未接入，不等于待重新设计。初始未支持不构成永久禁令，完整能力仍按 Roadmap 补齐。
