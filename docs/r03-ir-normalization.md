## 中端实现与 IR 基础设施 — Q4 accepted

R03 中端使用 C++，复用 MLIR 基础设施承载自有 Core IR 语义；HIR 仍保留独立高层职责。FrontendSnapshot 是拥有的前端事实输入，HIR 表达高层程序，Core IR 在双后端消费前完成语义归一化。R03 Core IR 和 R07 后端 lowering 的差别由语义阶段及不变量定义，不能仅因同用 MLIR 框架就混成一个阶段。

复用官方 SSA、验证、打印、序列化及 pass 框架不自动提供 tsfg 语义。数值、trap、求值顺序、Semantic Fuel、闭包、借用/效果和异常仍需 tsfg 的正式操作、分析及验证；使用官方操作时必须证明相应语义和前提匹配，不能把未定义行为或推测执行带入 tsfg 已定结果。

R02a 的 MLIR/LLVM 源码准入成为使用该基础设施的实际前置。沿用同级 Upstream Fork、完整 OID、Intake Ledger、锁定工具闭包、来源/许可和实际源码重建/消费验收；已有 Clang 工具或二进制分发不构成 MLIR 源码完成证明。该依赖不要求将 R07 的机器码输出一并实现。

VM 与 AOT 都从同一已验证 Core IR 降低；MLIR 序列化不作为游戏字节码，发布 Zig Runtime 不携带前端、MLIR 或 LLVM。既有官方 Go 前端及产品 Snapshot interface 继续按其职责演进，宿主语言选择不授权重建 TS checker。持久取舍见 [ADR-0015](adr/0015-mlir-backed-core-ir.md)。

## 编译闭包与泛型包 — Q5 accepted

Compilation Closure 包含明确输入、模块初始化、宿主可调用导出/回调、热更和内核入口及其依赖与可达实例。仅从一个 main 收集直接调用不足以涵盖实际入口；可达剪裁不能绕过正常源检查或模块初始化语义。入口与依赖必须能从输入及配置追溯，不以文件系统扫描或运行时发现决定。

泛型按具体类型实参特化，同实例复用，允许普通递归；无限增长或超过显式编译预算时诊断拒绝，规则继承 R01。最终执行 Core IR 只含具体实例；泛型预编译包保留可继续特化的自有、版本化、类型化定义，不能仅凭 .d.ts 或有限预生成实例声称完整包消费。

该包能力必须复用官方类型规则并提供正式前端适配。现有 checker 有实例化框架，但目前 Snapshot 只提供标量事实，没有已验收的泛型定义及实例化后函数体事实投影；官方懒求值对象和会话内 ID 不能作为持久包数据。R02b 的类型事实扩展、包输入到官方分析的适配及必要投影是明确依赖，不能在 R03 另造一般 TS 类型计算来填缺口。

R03 负责泛型表示与特化，R04/R12 负责交换格式和包消费者。完整验收须包括脱离原源码后新增合法实例、适用条件/映射类型、递归复用、增长/预算拒绝以及前端会话关闭后的正式 lowering；具体导入适配与字段由 spec/实施根据事实固化。取舍见 [ADR-0016](adr/0016-closed-program-specialization.md)。

## 强制静态安全边界 — Q6 accepted

跨函数和间接调用须推导及传播真实借用/效果摘要。对逃逸借用、内核禁入和并行访问集合等强制静态条件，仍无法证明时给出具体原因与调用链并拒绝相关操作；源码注释承诺、静默串行化或运行时兜底不能替代这些证明。

普通受管函数不因效果广泛而一律拒绝；既有动态边界、句柄及生命周期检查按其契约保留。分析未实现必须报告待实现，不能与完成分析后的证明失败混同，也不能以全拒绝声称分析能力已完成。验收同时包含可证明的真实正例、非法负例、跨调用传播和适用间接调用场景。

## 宿主语义契约 — Q8 accepted

可分析的 tsfg 实现及包按实际内容推导借用/效果摘要。不可分析的 Zig/原生实现由正式绑定提供 Host Semantic Contract，明确其借用、回调执行/保留及适用效果，版本化并绑定具体实现身份，以实现审查和真实行为测试建立可信输入。ABI 签名或布局相同不能证明回调不会被保存，普通源码注释也不构成证明；不为此新增 TS 语法或要求用户给普通函数手写完整效果集合。

该契约是分析信任边界，不是自动证明任意原生代码安全。契约缺失、不匹配或不可信时，强制静态安全场景按 Q6 拒绝相关操作；普通受管调用采用保守摘要，宿主能力授权及既有动态边界检查继续生效。能力授权不替代借用/效果契约，亦不通过人工权限审批代替语义验证。

R03 消费、传播及验证适用摘要，并给出调用链诊断；R04 提供实际使用的版本化交换与身份，R06 的正式宿主绑定及生命周期消费者提供可信实现与测试。至少覆盖同步且不保留回调的正例、保存含借用回调的拒绝、跨调用传播，以及缺失/不匹配契约；正式执行测试不能由签名匹配测试代替。

## 发布调用契约与推导事实 — Q9 accepted

保留每个实现的真实推导摘要，同时以 Published Call Contract 作为可替换函数对调用方的固定保守上界。首版可从推导事实产生；新实现必须满足既有上界。效果收窄可保持发布契约及其 hash 不变，超出上界须重新分析调用方并协调更新，不能以函数级补丁静默扩展。

对可替换函数的调用，调用方、内核合法性及并行访问分析以发布上界为依据；不能依赖当前函数体更窄的摘要形成未经约束的安全结论。推导事实仍用于检查实现满足契约，不因固定上界停止真实分析。签名/效果等 exact-match seam 继续比较发布契约身份；不把 hash 改为方向性兼容，不把实现身份与调用契约身份混为一谈。

R03 提供推导、满足性检查及实际依赖关系；R04/R09 负责格式和发布消费，不把完整热更协议划入 R03。验收包括效果收窄保持契约身份、越界写入拒绝、跨热更调用传播，以及旧调用方不会因实现暂时收窄而失去安全保障。取舍见 [ADR-0018](adr/0018-fixed-published-call-contracts.md)。

## 语言异常与请求终止 — Q7 accepted

Managed Exception 沿用普通 TypeScript throw/catch/finally 规则。语义 trap（含 Fuel/调用深度耗尽）与 Execution Abort 终止本次请求，不由语言 catch 捕获，也不继续运行用户 finally。

Runtime 负责必要的帧、GC 根、借用和宿主边界清理；这些是运行时自身操作，不运行用户回调，不回滚已发生效果。R03 显式区分语言异常传播与请求终止，R05/R06 联合验证实际执行、清理及宿主可继续接受请求。取舍见 [ADR-0017](adr/0017-request-termination-skips-user-finally.md)。

## 联合、缺失状态及异常载荷 — 沿用既有规则

联合按官方 TS 规则检查与收窄；编译器负责静态可确定的类型化存储，不要求源码手写全部标签，也不退化成一般 JS 动态值。值/引用分类由可能载荷决定：含直接受管引用的备选须保留根信息，不能按联合语法外形将其当成无 GC 值平面或内核数据。已证明的收窄可获得具体合法值；ABI 标签联合的每个备选仍须 ABI-safe，普通受管引用不得以裸指针跨 Zig，须通过显式 Handle 边界或拒绝该边界表示。

保留 null、undefined，以及属性不存在与存在但值为 undefined 的适用可观察区别。标签编号、presence 编码和槽分解由正式表示与消费者确定；verifier 必须拒绝不合法标签和未证明的载荷访问，活动引用、可空引用与异常传输载荷在 safepoint、移动 GC、展开、catch/finally 和重抛中须正确保活/重定位，未激活标量比特不能误作引用。

Managed Exception 保留适用标量/值/引用载荷及其值或身份，catch 的 unknown 视图按既定规则收窄，不恢复单一名义异常基类要求。正式类型化异常传输不要求把每个标量隐式包装成 GC 对象，也不允许只传错误码而丢失载荷；含借用的载荷仍受真实传播路径的生命周期/逃逸规则约束。存储算法可替换，但不能创建临时执行器或合并 Q7 已区分的终止通道。

R02b 的 owned 联合/收窄/属性/异常事实仍是实际前端依赖；R03 完整实现表示、归一化及验证；R04 提供当前交换/ABI 消费约定，R05/R06/R07 提供正式载荷、根与执行消费者，R08 以独立 oracle 核验，R10/R11 验证适用内核拒绝与收窄正例。必须覆盖混合联合、缺失状态、标量/引用抛出与重抛、嵌套 finally、GC 压力/移动、错误标签/根信息、借用及裸引用 ABI 负例；不能因当前 Snapshot 仅标量而删减这些职责。这些是既有语义的工程责任，不新增语言选择或 ADR。

## 无损字符串与严格 UTF-8 视图 — Q10 accepted

普通 tsfg String 保持既定 TS UTF-16 码元行为及值域，内部采用 canonical WTF-8 无损保存，包括孤立代理码元。canonical 指编码及代理对的规范表示，不进行 Unicode 文本归一化；逻辑长度、索引、切片、比较及拼接不能由字节长度、字节切片或字节顺序替代。源码仍为 UTF-8，源码位置仍按既定 UTF-16 区间，两者不从运行时字符串存储反推。

StringView 是严格 UTF-8、字节长度的受控借用。合法 Unicode 文本的内部字节保留 UTF-8 常见路径；无法严格输出的字符串明确失败，不静默替换，有损转换仅由调用方显式选取。视图只暴露约定字节范围，不以 String 对象地址表示宿主引用；Runtime 须保证来源保活、字节地址稳定和不得越期保留，编码一致不能代替这些证明。不承诺任意普通 String 自动零复制跨界；显式转换与 ABI 传递分别承担其实际成本。

R02b 必须从官方前端投影保值的字符串常量与类型事实，不能将孤立代理码元的内部 sentinel 直接交给会替换非法 UTF-8 的普通 JSON string 序列化。R03 实现常量、码元操作、受管引用分类、视图转换/借用及优化保真；R04 为实际 payload 与视图规定保值编码、版本和损坏拒绝；R06 提供正式字符串、保活/稳定及边界消费者，R05/R07/R08 提供正式 VM/AOT 执行和独立 oracle 验证。具体 API、索引缓存和序列化字段由真实消费者固化，不新造语法。

验收包括补充字符、两个方向的孤立代理码元、拆开后拼接、码元比较、空串/NUL、严格出口成功/失败、显式有损转换，以及前端会话关闭、序列化和 GC 压力下的保值与视图寿命。官方 scanner 现有能力不证明这些产品能力已实现。取舍见 [ADR-0019](adr/0019-lossless-strings-strict-utf8-views.md)；事实依据见 [RFC 3629](https://www.rfc-editor.org/rfc/rfc3629#section-3)、[ECMA 字符串值定义](https://tc39.es/ecma262/2022/multipage/ecmascript-data-types-and-values.html#sec-ecmascript-language-types-string-type)及 [WTF-8 定义](https://wtf-8.codeberg.page/)，不升级产品 TypeScript 基线。

## 活跃借用与容器结构 — Q11 accepted

Span Borrow 活跃期间，所借容器的拥有者、缓冲区及有效范围保持稳定；任何别名不得改变其长度/容量，或释放、转移该缓冲区。不凭某次 append 恰好无需重分配就放行；按真实最后使用点结束借用，之后恢复普通密集容器结构修改。

普通 Array 的共享别名/身份及浅 readonly 沿用既有原则，不改成 move-only、隐式复制或 COW；串行已有元素写入仍可对视图可见，ReadSpan 不构成全局冻结或 Rust 独占规则。并行/内核按实际访问集合及既有要求证明，不从串行可见性推出并行合法。借用分析和 Q8/Q9 调用摘要必须处理别名、派生视图、同步非保留回调及真实最后使用点；证明不足时拒绝相关借用操作并给出原因/调用链，不新增动态拥有者冲突检查作为兜底，也不以全拒绝冒充完整分析。

原生共享拥有者、返回/闭包寿命和正式回收由 R06 提供实际接口，R03 保留身份、借用和效果关系；不能以栈描述符复制或词法 arena 冒充跨调用寿命，返回/捕获拥有的 Array 与逃逸 Span 不混同。引用元素另需正式根/写屏障/移动更新，原生分配或引用计数不自动证明 GC-free 或完整回收。该职责不在本轮改选 GC 拥有原生 payload。

验收必须包含直接/别名/跨调用结构冲突、合法视图返回、同步回调、最后使用后结构修改、串行元素可见性、引用元素移动及请求清理；正式消费者缺口仍是具体 R02b/R04/R06/VM/AOT/领域依赖。取舍见 [ADR-0020](adr/0020-stable-container-during-span-borrow.md)。普通动态索引及密集结构操作的范围检查另行界定，不从 Q11 推导为所有边界必须静态可证。

## 已定容器读取与后续流程

继续核对完整 R03 中仍需选择的工程取舍。宿主摘要来源及推导事实与发布调用契约的关系已经确定，不重复提问。IR 所有权、pass 失效、序列化、身份、确定性和 verifier 要求须在后续规范及真实消费者中具体落实；可替换算法和字段不逐项提交用户问答。

字符串、活跃借用及混合联合边界已定，正式语义/Runtime/ABI 消费者及验收仍是完整 R03 的具体责任。泛型包前端适配、MLIR 源码准入和新增前端事实未验收前，不能记为可用。

2026-09-30 用户接受 Q12 B：普通密集 Array 下标读取有效元素时返回 T；缺失/越界必须在原生元素访问前产生结构化语义 trap，不返回作为缺失哨兵的 undefined，不补零或读取未初始化存储。T 自身包含 undefined 时，有效元素的 undefined 仍是正常值，不能与索引缺失混同。这是相对于普通 TS/JS 缺失读取返回 undefined 的明确必要差异；连续同构元素布局本身并不迫使采用该政策，读取结果 union 也不自动要求逐元素装箱。取舍见 [ADR-0021](adr/0021-checked-native-array-index-read.md)。

该 trap 沿用 R01/Q7：终止本次请求，不进入用户 catch/finally，不回滚先前效果；Runtime 清理自身必要资源并保持宿主存活。Core IR 与正式 VM/AOT 必须保留接收者/索引及其他表达式的既定求值顺序、首个失败、源码锚点和先前可观察效果；不能在未到达路径提前失败。只有证明当前读取有效且相关长度稳定时才可消除检查，as/非空断言或 checker 假定 T 不构成原生访问存在性证明，不声称 B 已有性能优势。

正式验收须有独立 tsfg 差异 oracle：首/末有效元素、空数组、索引等于长度及远越界、元素类型含 undefined 的有效值、断言后的缺失读取、未到达分支、求值副作用与首个失败、失败前宿主效果保留、用户 catch/finally 不执行及 Runtime 清理/宿主存活；分别在真实 VM/AOT 消费者验证结果、失败位置与时序，不能仅以两后端相互一致代替 oracle。

官方 noUncheckedIndexedAccess 当前未启用，也不由 strict 自动开启；Q12 不批准开启该 flag。正式 checked T-read 与官方类型事实、必要 tsfg 特殊映射及版本化前端/IR 交换契约须协调，保留其他诊断，不另造一般 TS checker；具体字段、错误码、配置和消费者由规范/实现固化，本轮不修改机器契约或宣称实现。允许查不到的业务可另设计显式可选查询方式，但名称、签名和具体接口未批准。

## 动态密集操作与 Span 边界 — Q13 accepted

2026-09-30 用户选择 Q13 A：支持合法动态已有元素覆写、恰好末尾追加及缩短；制造 gap/holes、增长出未初始化元素等静态已知非法形式编译期拒绝。受支持操作的动态索引/长度按实际执行检查，违反密集/已初始化不变量或 Span/ReadSpan 越界时，必须在非法内存访问或该次非法修改前产生结构化语义 trap，不先制造 gap、不读取原生垃圾、不自动零填充。对长度为 2 的 Array，动态索引 1 可覆写、2 可追加、4 不能跳写；缩短为 1 可合法，直接增长为 4 而未初始化新增元素不合法。这些描述限定语义，不批准新的标准库 API 或可选查询接口。
