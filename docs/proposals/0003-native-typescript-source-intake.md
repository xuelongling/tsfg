# ECP-0003：官方 TypeScript 原生源码准入与构建闭包扩展

Status: accepted
Date: 2026-09-10
Authorization: 用户对 R02a Q1–Q4 回复“全部接受”，随后明确 Q5 在 fork 新特性分支直接改动、Q6–Q9 按推荐接受。仅批准下述设计边界，不授权本轮实施或远端操作。
Decision Owner: 用户
Scope: 首个 TypeScript Source Intake、所需 Go 工具闭包及既有跨仓准入规则的受控扩展。

## 背景与决定

R01 已固定 TypeScript 7.0.2 语言基线。实际官方前端为 Go 原生源码，而工程 TypeScript 开发依赖不提供该基线的源码接入。既有 R00 gate 为未批准任何 fork 的状态，不能直接接入新来源。

选择 microsoft/TypeScript 的 7.0.2 原生源码，base commit 为 `1e4744d68260a7cb91b62b12edc3f6a2187faaf1`，按 [R02a 规范](../r02a-source-intake.md)执行准入与双路径源码重建验收。必要 Go 工具/依赖按现有 Toolchain Closure 规则纳入；这不是对未审计依赖、自动工具下载或系统 PATH 回退的豁免。具体工具补丁版本和可信内容身份须在实施前核验并锁定。

保留完整上游历史和原始来源/许可文件，用机器展开消费文件清单、人工解释修改与例外的方式履行逐文件审计。仅批准来源及其实际消费闭包可进入 manifest/构建策略；未消费内容仍排除。

Q5–Q9 补充：在 fork 新建 tsfg 特性分支直接修改必要源码，不把薄 wrapper 作为唯一允许的修改方式。允许分析/诊断必需的共享 printer 与包级构建依赖，但必须证明产品入口不可启用 JS 输入/输出/runtime 回退；无隔离证据不得准入。实际消费的生成源码在首次 intake 与生成输入变化时重演验证。升级保留已接纳历史，逐候选审查；漏洞按消费角色和可达性判断，受影响候选执行规范中的阻断与例外授权规则。详见 R02a 规范，不新增通用桥接、自动升级或安全运营平台。

## 影响与不变量

- ADR-0004 的统一控制面扩展以容纳锁定 Go 构建，不另立公开构建系统；其他原生工具与 profile 规则不被默默重写，Go 的具体 profile 映射待核验。
- 产品与 Manifest Repository 的准入/证据消费者需要协调更新；本 ECP 不批准修改现有 snapshot/tag 历史，不创建 Stable，不扩大 `.agents` 构建输入。
- Build Identity/Build Input Set/Toolchain Closure 的现有身份定义不改；新增实际输入按已有机制显式纳入，而不是忽略新工具/源码的影响。
- 来源、许可证、NOTICE、离线边界、路径安全、无 secret CI 和发布权限保持有效。source 审查完成前不得宣称来源已可合入或分发。
- 新增 Go 仅限编译器侧；不把 Go、TypeScript 或 LLVM 引入 Zig 游戏发布运行时，不允许 JS 输入/输出/runtime 回退。

## 备选与取舍

- 旧 TS 实现/Compiler API：接入经验多，但不能未经证明就替代已定 7.0.2 基线。
- 等待未来公开 API：减少内部接口维护，但把首条链路绑定未验收的外部计划。
- 采用固定官方原生源码：保持基线与可维护来源一致，代价是新增 Go 闭包、内部接口审计和必要 fork 修改。具体出口实现与消费者的通信/链接形态在对应工程阶段验证，不作为本轮新增平台设计。

## 验证、迁移与回退

后续实施按来源验证完整 OID、消费/许可映射、缺失与篡改拒绝、真实接口正反例、两个干净路径重建及输出比较。产品与 manifest policy 同步交付，不能只修改 XML 后跳过旧 gate。

发生不符合基线、许可证不清、输入完整性失败或不可复现时，不将该候选晋升为可消费来源；保留证据并返回先前已验证组合，不修改历史身份。调整语言基线、新来源或越界安全例外另行决策。

本 ECP 不授予 fork 创建、clone、安装、提交/推送、权限调整或正式发布的执行授权；本轮不产生上述行为或验收证据。
