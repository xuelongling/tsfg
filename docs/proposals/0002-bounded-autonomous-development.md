# ECP-0002：范围预授权的 Windows 自主开发

Status: accepted
Date: 2026-09-08
Authorization: 用户审阅自主开发流程调研后明确要求“改造下”。批准本提案的本地流程调整，不代表已批准任何具体管理员部署或远端操作。
Decision Owner: 用户
Scope: 已批准 Windows 开发任务的执行、开发契约有限委托、受约束工具准备与权限阻塞处理。

## 背景与目标

ECP-0001 已把开发与正式发布分开，但普通任务重复确认、开发契约的一概人工批准和 Bootstrap 手工限定仍可能阻断连续工作。Windows 工具审批与操作系统访问令牌也被混作同一种授权。

目标是让已批准范围内的实现、测试、修复和取证连续执行，把用户决策集中到实际越界处。机器检查仍严格执行；没有证据的状态保持未完成。本提案不改变 R00/W0–W7 的能力范围，不批准新 upstream、远端写入、提交/推送、发布、安全绕过或系统配置变更。

## 决定：范围内自动，越界才决策

任务的授权范围来自用户请求或用户批准的规格/能力票，至少能确定仓库、用户能力、非目标与验收条件。Agent 可补齐普通实现细节、分解子票、做可逆本地修改、运行适用检查、修复失败、整理证据并关闭已满足全部条件的票。不能把 Roadmap 的远期规划、Agent 自写提案或历史授权变成新的执行授权。

遇到失败先做安全、相关、范围内的诊断；测试失败本身不是人工实施要求。只有缺失具体权限、不可推导的产品取舍、来源/许可证疑义或其他边界冲突才请求用户。已确认且条件未变的选择不重复询问。只阻断受影响任务；同一活动任务内的无关且已授权工作可以继续，不主动接管其他会话。

## 开发契约的有限委托

以下条件全部成立时，用户通过本提案预授权 Agent 完成开发契约的版本决定与实现，无需每次另开 ECP 或等待人类 Owner：

1. 属于已批准功能切片；所有实际 producer/consumer 都在同一产品仓并能原子更新。
2. 该格式尚未发布或承诺兼容，没有依赖旧格式的受支持外部消费者；不能仅以版本低于 1.0 作判断。
3. 不改变 Build Identity/Build Input Set、隔离/信任边界、已支持接口、跨仓契约或既有兼容窗口。
4. 更新真实规范与版本决定、适用 registry/schema/hash 和全部实际消费者；旧缓存失效、旧格式/混合版本/损坏输入拒绝及相关正确性测试同步交付。
5. 保留 Standards 与 Spec 两轴评审结论和测试证据。可用 Agent 评审辅助检查；没有独立评审时如实注明，不冒充人类或独立审核。

任一条件不成立，仍按原 Owner/ECP 规则处理。委托不允许 Agent 扩大委托自身、降低验收或批准 Stable。开发契约的局部版本记录不能代替正式发布兼容性审查。

## 工具与 Bootstrap

取消“必须人工输入安装命令”和“一概不创建 repo 安装脚本”的执行方式限制。允许为已授权任务自动准备既有批准来源的锁定工具，或按原规则完成补丁升级；同一来源的补丁升级并非自动可信，仍须验证精确版本、独立可信来源的摘要/签名、许可证、归档/解包完整性及兼容性。不能自行接受摘要不符、从已下载文件反推可信期望摘要或静默使用系统 PATH 回退。

工具链 major/minor、新信任根/来源、未解决许可证问题和工程边界变化仍先决策。安装前确认下载、解包、子进程 TEMP/TMP、缓存、用户配置和日志实际落点符合 E 盘要求；不能先写 C 再迁移。需要服务、账户、注册表或其他系统管理状态变更时，先列具体副作用与现有授权的差异；本提案不授予系统盘例外。

Bootstrap 的角色、固定 repo 版本/摘要、manifest 完整 OID、来源与链接校验不变。自动化须有可维护源码、明确输入、可重跑命令与失败记录，Manifest README 继续是初始化契约入口。本次不修改 Manifest Repository 或运行安装器。

## 操作系统权限与执行会话

任务授权、Codex 工具审批和 Windows 实际令牌是三个不同条件。权限错误须报告实际令牌/能力、失败操作及最小所需变更，不能重复请求抽象的“完全授权”。在相同事实下不反复弹起 UAC，也不能关闭 UAC、放宽全局 ACL 或用不满足隔离要求的运行方式冒充通过。

后续执行器目标是一次明确批准、范围与期限固定的受限会话。特权部分仅管理必要隔离；可修改的仓库脚本、Node 控制面及构建/测试后代都以低权限运行。IPC 必须校验本地调用者、能力、路径和输入身份，拒绝任意管理员命令。单个任务失败不撤销有效会话；到期、撤销或隔离失效则终止关联任务并清理自有状态，避免规则消失后任务继续运行。不得影响别的会话。

现有执行器尚未证明满足该目标；在独立源码、负例及 Windows 实测完成前，仍遵守现有适用隔离门。新会话、能力扩大、执行器/特权策略变更需要核对具体授权，不能继承对旧脚本的笼统同意。本提案不安装服务、创建计划任务或把 Codex 整体提升为管理员。

## 备选与取舍

- 保持逐次人工审批：实现简单，但人类成为每次失败修复与格式演进的串行依赖。
- 全局管理员或取消隔离：减少提示，却扩大可修改代码的权限，不采用。
- 本决定：一次定义可自动执行的范围，机器保留证据门，越界才决策。代价是需要明确例外分类，以及单独实现并验证最小权限会话。

## 验证、迁移与回退

本次验证只覆盖文档链接、规则一致性、Agent 入口与正反场景，不证明运行时权限隔离或 R00 完成。将普通实现、符合委托条件的格式演进、已锁工具准备作为继续场景；已支持契约破坏、陌生来源、隔离失败、系统写入例外与发布作为停止或另取授权场景。

受限会话只有在真实多轮失败修复无重复 UAC、所有任务低权限、越界拒绝、崩溃清理与 E 盘路径均有证据后才可标记完成。历史票和主任务证据不改写；后继工作单列，不将计划记为成功。

需要撤销委托时由用户明确决定并记录 superseding ECP；保留本提案历史，后续变化回到相应 Owner 决策，不回写已产生的证据或版本身份。
