# 解释器执行优化与验收（R05 / R08 / R10）

状态：2026-10-28 采纳的设计与任务细化；不表示实现或性能验收已通过。本文落实[架构](tsfg-architecture.md)中的预解码、专用指令、缓存与超级指令，沿用既有数值、预算、调用和根生命周期语义。

<a id="delivery"></a>

## 1. 按实际依赖交付

| 工作 | 归属与前置 | 交付条件 |
| --- | --- | --- |
| 正确的预解码执行基线 | R05；已有字节码和当前 Runtime 接口 | 真实源码执行、验证器拒绝、预算及源码定位正确 |
| 紧凑执行数据与少量超级指令 | R05 / R08；对应能力已具备正确性基线 | 受影响语义回归通过，测量执行时间与内存变化后决定具体表示和融合集合 |
| 尾调用分发、物理寄存器缓存 | R05 条件性实验；实际工具链可表达 | 与同配置现有分发比较，验证宿主栈、ABI 和 safepoint；仅保留有收益的方案 |
| Chunk 批量解释执行 | R10 / R05 / R08；类型化内核、布局、借用及效果证明 | 满足第 5 节的语义条件并通过标量对照；不依赖 AOT 向量化完成 |
| AOT 向量化 | R10 / R07 / R08；对应后端能力 | 同一内核语义下验证并测量，不以基础 ISA 与增强 ISA 的差距证明解释机制更优 |

这些优化不阻挡首条正确执行链，也不新增完整 R03 的关闭条件。实现复用已有正式入口和合格结果；每项改动只增加受影响检查。运行时使用预编译 handler，不在请求执行期间生成机器码或引入 LLVM；现有编译服务与原生补丁生命周期仍按 R09 处理。无 JIT 不自动证明其他平台准入。

## 2. 预解码与执行数据

- 磁盘字节码保持现有版本化编码；验证完成后，加载器生成内部拥有的执行数据。内部布局、进程地址与磁盘契约分别管理。
- 优先测量热循环读取的数据：opcode、操作数、立即数及必要控制流信息。源码、诊断和其他低频元数据可通过明确索引置于旁表，保持原指令定位、异常及根信息可取得。是否分离由实际访问和内存测量决定，不先固定结构大小。
- 首版优先不可变执行数据。直接线程化的函数指针、索引或其他分发表示按同一负载比较；文件输入不提供可执行地址，内部地址只由加载器从匹配签名的已知 handler 生成，不序列化或跨进程复用。
- 变换保留分支目标、寄存器类型、所属函数和验证结果之间的关联。额外展开内存、加载时间及重复加载/卸载的寿命计入资源检查。
- `switch` 是有效基线。比较最终生成代码及实际负载，不以源码含 `switch` 推断必然存在低效分支链。

## 3. 超级指令保持原语义事件

从实际高频的短序列选择少量融合模式；使用既有 Core/字节码降低职责，不另造语义解释器。内部执行表示可以先融合，确需新增磁盘 opcode 时才按真实 producer/consumer 更新契约。

融合必须保持：

- 原始求值顺序、首次 trap 的位置及此前可观察写入。原序列中可单独进入的控制流位置仍有正确入口，不能让分支落入不可进入的融合内部。
- Semantic Fuel 的逻辑事件和检查顺序。物理执行配额单独定义与测试，不能因一次 handler 覆盖多项工作就漏掉资源约束，也不能把物理指令数改作语言 Fuel。
- safepoint、根状态、异常传输和源码/调试位置；调试执行可以选择已验证的未融合表示，但须保持同一语言行为。
- 严格浮点每步舍入、NaN 与次正规数规则。合并分发不授权将乘法加法换为 `@mulAdd`、重排归约或启用 fast-math；沿用[浮点契约](r03-float-vm.md)。

验证包含正常结果、原序列各可能失败点、Fuel 边界、此前副作用、跳转/循环及当前能力适用的 GC/异常场景。收益测量同时记录融合 handler 代码体积，避免无界扩充指令变体。

<a id="dispatch-cache"></a>

## 4. 调用约定、根与缓存

尾调用和寄存器缓存属于可选实现。先证明锁定 Zig/LLVM 工具链、目标和构建配置能够表达所需调用约定，再比较实际代码与性能；LLVM 的 `ghccc` 与 `preserve_nonecc` 不等同，也不能当作 Zig 同名 API。`preserve_none` 对通用寄存器的规则不自动覆盖浮点/向量寄存器。[LLVM 调用约定](https://llvm.org/docs/LangRef.html#calling-conventions)

验收覆盖长指令链不增长宿主栈、寄存器搬运/溢出成本、慢路径及宿主调用、正常返回与失败清理。解释器内部约定通过明确桥接接入外部 C ABI；handler 尾调用不改变语言活动调用深度。

寄存器缓存和引用/标量槽分区不代替根协议：safepoint 前活动引用、参数、返回值及临时值对收集器可见；移动后更新或重载缓存。联合类型活动载荷、失活槽和内部地址按[根与地址验收](execution-boundary-acceptance.md#gc-lifetime)处理，不承诺零成本 GC。

不可变模块内的类型、偏移和固定签名检查可按其有效期在加载时完成。热更目标、能力与执行上下文相关的缓存须绑定对应身份/版本和失效条件；一次调用成功不能使其他版本或请求自动获得同样结论。

原地 quickening 不作为首版要求。若实际负载需要它或可变调用缓存，先定义完整缓存记录的发布、失效与回收；原子写一个 handler 指针不证明目标、代码版本、环境与元数据一致。复用[跨 Tier 发布及生命周期验收](execution-boundary-acceptance.md#tier-calls)，包括旧调用延迟完成、版本交错和失效缓存。

## 5. 批量解释执行与 SIMD

对已有合法性证明的 Query/Chunk 内核，使用预编译批量 handler 均摊分发成本，保持 VM/AOT 同一用户模型和访问集合。首批不预定向量 opcode 数、批长或 SIMD 宽度；由实际字段、访问方式和目标决定。[DuckDB 向量执行参考](https://duckdb.org/docs/current/internals/vector)

把逐实体执行改成逐操作批处理前，证明跨实体依赖、读写重叠、别名、顺序和失败行为允许该变换。例如原循环先写 `position[i]` 再执行可能 trap 的计算，提前写完整列会改变首次失败前的状态；存在这种差异时保持既定标量顺序。并行内核使用其明确的并行语义，不从优化手段倒推新的语言行为。

验收至少包含：

- 实际元素数不是向量宽度整数倍、空批次、非增强对齐及声明允许的重叠访问；合法情况结果正确，非法情况在既定边界拒绝。
- 条件掩码/selection vector 保留短路、索引顺序和副作用；不执行原程序不会触及的有副作用或可能 trap 的元素操作。
- 首次 trap、Fuel 耗尽、取消与此前写入保持相应语义；分配/GC/宿主调用等不满足内核约束的能力仍按已有规则拒绝。
- 严格浮点与标量结果关系、NaN/有符号零/次正规数；只有另行定义的数值契约允许改变舍入或归约顺序。
- 基础实现及每个增强 ISA 实现都经过验证；运行时分派检查 CPU 与 OS 可用状态，尾部处理及不具备增强特性的路径可执行。

VM 与 AOT 可以各自采用同语义的预编译多版本内核。批量 VM 验收先与独立预期结果和标量执行比较；AOT 对应能力完成后补差分，不以未来 AOT 为批量 VM 启动前置。

## 6. 测量与任务收口

性能任务在运行前明确负载、硬件、配置、比较基线、目标指标和可接受代价。分别测量加载/预解码、热执行、低频大代码路径、调用/宿主边界及适用的批量内核，报告延迟、吞吐、展开内存和 handler 体积；不为未涉及的能力追加整套测试矩阵。

比较固定语义、CPU 特性、线程、检查和优化配置。不同 ISA 的部署配置可以单独报告，但不能作为解释器与 AOT 执行机制优劣的同条件结论。基于函数/指令采样选择融合模式不等于开启编译器 PGO；构建继续遵守[工程章程](r00-engineering-charter.md)的配置规则。

CPython 的尾调用解释器数据是相对其原解释器的特定配置结果，且官方说明验证配置使用 PGO，不能移作 tsfg 的收益保证。[CPython 3.14 说明](https://docs.python.org/3.14/whatsnew/3.14.html#a-new-type-of-interpreter)

不预设相对 AOT 的百分比，也不把代码对齐/小体积解释成锁定 L1i 或零 cache miss。正确性、收益与代价分别记录；没有收益的条件性实验可据结果结束，不升级成必做架构。每票沿用一份摘要，记录实际改动、适用检查/评审、测量结论和仍未验证部分；既有执行限制不随本文解除。
