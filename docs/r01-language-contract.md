# R01：规范化语言语义与一致性测试语料

状态：设计澄清已收口，可进入 to-spec；更新于 2026-09-09。本文件只包含当前有效决定、首批覆盖及明确后置责任，不表示 R01 已实施或验收通过。

本文件细化 [架构](tsfg-architecture.md) 与 [Roadmap R01](tsfg-roadmap.md#r01规范化语言语义与一致性测试语料)。问答历史保留在 workspace tracker，不作为另一套实施约束。此次收口不创建 spec/tickets，不授权源码接入或实现代码。

## 1. 路线、基线与职责

默认沿用 TypeScript 7.0.2 基线的词法、语法、类型检查与语言行为；仅本文件及架构明确列出的必要差异由 tsfg 规定。直接复用官方 scanner/parser/AST 及适用的 checker、收窄、模块解析、诊断与 Language Service 源码，在同级 Upstream Fork 中进行最小客制化，不全量自建替代前端。

固定语言基线、实际接入的源码 commit/接口路线、工程控制面 devDependency 是三个不同身份。基线升级须复核差异；源码与接口必须在 R02a 核验其对基线的支持，不能以已有包或 dist 证明已有可维护前端。本次没有选定源码 commit、升级工具或宣布任何语言能力已实现。

跨阶段方向为 source → 官方 TypeScript 前端 → tsfg HIR → tsfg Core IR → AOT lowering。2026-09-30 R03 Q4 已确认由 C++/MLIR 基础设施承载 Core IR；语义归一化和后端 lowering 仍是不同职责：

| 责任 | 所属阶段 |
| --- | --- |
| 引用上游规则/测试，规定必要差异、支持矩阵及 Conformance Corpus/oracle | R01 |
| 实际源码、许可证、固定 commit 和可复现接入 | R02a |
| 官方前端接入及 FrontendSnapshot、输入和诊断边界 | R02b |
| HIR/Core IR、语义归一化及 verifier | R03 |
| Core IR → 后端 dialect/LLVM/AOT | R07 |

R01 不重写 TypeScript 规范，也不将上述编译链的实现塞入自己的验收。通用语言在 W3 收口，CPU/GPU 领域语义随 W4/W5 收口，W6 覆盖全部适用语言规则；首批切片不代表整个 R01 完成。

## 2. 沿用规则与能力状态

### 2.1 沿用 TypeScript

下列事项直接引用固定基线及官方实现/测试，不再逐项征询或自定义：

- 词法、ASI、Unicode/转义标识符、数字分隔符、优先级、结合性及换行敏感解析。
- 名称解析、作用域、一般赋值与函数表达、控制流、普通类型关系及适用的类型工具。
- 普通类的源码赋值兼容性、构造/方法行为；不能从 GC 对象身份推出所有普通类都必须名义赋值。
- 空值收窄、optional/default parameter、readonly 的通常语义，以及闭包对逻辑绑定的捕获。
- 静态 import/export 的 live binding 和普通 throw/catch/finally 行为。是否为模块按所采用的官方项目配置及源码规则判定，不自定“每个文件天然是模块”。

readonly 不等于深冻结、无可写别名或借用/并发安全证明。默认参数在省略或 undefined 时触发而非 null；导入绑定不可重绑不代表导出对象深冻结。这些是沿用行为说明，不是独立的语言设计。

未扩展语法必须接受完整 grammar 检查，不能按某个 diagnostics API 的名称机械划界，也不能整体忽略上游错误来放行扩展。无法 lowering 的合法 TS 结构应报告能力状态，不能冒充语法错误或改变解析含义。

### 2.2 支持矩阵

矩阵的语义来源与实现状态分别记录：

| 分类 | 含义 |
| --- | --- |
| 沿用基线 | 官方规则已定义，不因本文件未重述而变成“待规范” |
| 必要差异 | 有架构需求、规则和对应 oracle 的 tsfg 特殊行为 |
| 待规范差异 | 后续具体消费者尚需明确的特殊映射，不是普通 TS 行为 |
| 待实现 | 语义来源已明确，但当前前端/lowering/执行未接入 |
| 当前支持 | 当前切片实际实现并通过适用验收 |
| 禁止 | 架构明确排除的输入或能力 |

前端接受不等于后端已支持；正确拒绝待实现功能也不等于该功能实现通过。新增版本不自动扩大已验收范围。详见 [ADR-0009](adr/0009-explicit-language-support-matrix.md)。

### 2.3 输入与明确排除项

源码/声明只接受 .ts、.d.ts，另接受预编译 tsfg 制品；.d.ts 不是 JS 实现。拒绝 .js/.mjs/.cjs、JS 包和字节码、隐式 JS 依赖或运行时回退。与 JS 共有的合法 TS 语法不因外观相同而拒绝，工程 Node 工具也不构成产品 JS 支持。

继续保留架构禁止的 any、eval、Function(string)、原型链修改、Proxy、动态属性增删、JS 稀疏数组/对象字典、隐式装箱、隐式数值类型变化和宽松相等。采用 TS 的规则及源码不等于引入 JS 引擎、emitter 或完整 JS 标准库；发布运行时不携带 TypeScript、MLIR 或 LLVM。

### 2.4 最小编译期标记

普通 TS 声明、类型和已有 API 优先；不能推导或清楚承载的必要声明意图才使用少量 Compile-time Marker。值/引用分类和组件身份需要显式选择；字段布局与读写集合由类型/分析推导。

先使用 TS 合法位置，只有真实消费者证明必要时才扩展位置或参数形式。架构中的标记示例表达意图，不冻结全部语法。注释主要用于文档；不预建通用 decorator 执行、宏、插件或新增关键字。首批 i32/bool 切片不需要这些设施。

## 3. 首批可验证覆盖

首个供 W1 消费的切片为单模块、顶层函数、显式 i32/bool 参数和返回类型，包含局部 const/let、简单赋值、算术/比较/短路、if/else、while、调用和 return，无引用分配。正例覆盖前向调用、直接/相互递归、求值顺序及结构化失败。

首批 fixture 使用已初始化局部变量、精确参数、明确返回路径和 bool 条件。未初始化 let、复合赋值、自增、赋值表达式、可选/默认参数等没有被重新定义或永久禁止：若未进入当前 lowering 切片，标待实现并明确诊断；不能把测试样例形状变成整门语言的限制。

完整数值族、引用、闭包、异常、多模块、容器和计算领域能力随对应切片接入，不阻挡首批 spec。每个切片继承已有 TS 行为，只补齐它实际消费的特殊规则；缺少后续能力的测试不能使整个 R01 被记为完成。

## 4. 已确认的数值差异

这些规则服务定宽标量、Zig 固定布局与双后端一致性，不是替代 parser 的理由。

### 4.1 类型与定型

- 无上下文整数字面量默认 i32；未定型字面量可按明确上下文定型，已定型数值不隐式转换。
- bool 为规范名，boolean 为别名，字面量为 true/false。ABI 的 u8 0/1 不构成源码整数到 bool 的隐式转换；number 固定为 f64。
- 整数 token 按精确数学整数读取，不先经宿主 f64。正字面量超范围是编译错误；一元负号直接作用于整数字面量时检查整体范围，i32 的 -2147483648 合法，0xffffffff 不自动解释为 -1。
- 小数/指数形式在无上下文时为 f64；有浮点上下文时从精确文本直接舍入目标类型，不经 f64 中间值。有限字面量舍入成无穷则编译拒绝，下溢按舍入规则可得到有符号零。
- 这些是数值定型规则；字面量拼写、token 和表达式结构继续由官方前端处理。

### 4.2 整数运算

- i32 加、减、乘、取负按 32 位回绕；除法向零截断，非零余数符号随被除数。
- i32 的 MIN/-1 为 MIN，MIN%-1 为 0；除零或余零 trap。
- 移位计数为 i32，i32 操作数允许 0..31，其他计数 trap；>> 符号扩展，>>> 零填充，结果仍为 i32。
- 原则按位宽推广至其余定宽整数；isize/usize 由目标 DataLayout 决定。普通算术和比较要求同型，移位允许 0..位宽-1；有/无符号边界随具体类型 fixture 验证。
- 常量折叠保持相同运行含义：不将运行表达式中的已知 trap 擅自改为编译拒绝，不提前触发未执行路径的 trap。

首批 bool 条件及 &&/|| 采用短路并产生 bool；操作数和实参从左到右求值，首个实际 trap 停止后续求值。禁止 ==/!= 来自架构的宽松相等禁令。首批 bool 覆盖不扩张为对所有后续 TS 条件表达的永久新禁令。

### 4.3 显式转换与严格浮点

显式转换区分范围检查、整数截位回绕和等宽标量位重解释；as 不承担数值转换。采用普通 TS 函数调用表达，不新增关键字。

范围检查不承诺精度无损：整数到浮点、浮点窄化按目标精度最近值/平局取偶舍入，有限输入舍入为无穷则 trap；浮点到整数先向零截断再检查范围，NaN、无穷或越界均 trap。

严格浮点每步在声明精度按最近值/平局取偶舍入，保留次正规数和有符号零，不隐式融合乘加。算术 NaN 规范化为各类型规定的 quiet NaN；数据搬运和位重解释保留原始位。浮点除零按 IEEE 产生无穷或 NaN，不沿用整数除零 trap。

具体转换入口、canonical NaN 位模式及函数覆盖在相应数值切片中固化为可核验记录。超越函数、fast-math、并行归约与 GPU 不自动继承严格 Execution Equivalence，必须有各自数值/确定性契约。

## 5. 数据、内存及领域边界

### 5.1 固定布局与受管引用

值类型和组件具有明确的类型/组件身份，相同布局不自动使其互换；普通值赋值、传参与返回按值复制，=== 按字段自身规则比较而非 padding。值类型/组件不继承；这些要求不扩大为普通类的一般名义赋值规则。取舍见收窄后的 [ADR-0011](adr/0011-nominal-data-types-structural-constraints.md)。

普通 class 为 Sealed Reference Type：字段固定，支持规定的单继承和覆写，由 GC 管理。复制普通类引用后仍指向同一对象，=== 比较对象身份；对象身份与 TS 源码类型兼容性不是同一概念。构造/readonly 行为沿用基线，不增加“构造期间一律禁止可覆写调用或 this 逃逸”的无条件源码禁令；实际内存安全检查须有表示/生命周期依据。

严格空值检查始终开启。null、undefined、void、never 及默认参数/optional 的源码规则沿用基线；不得读取未初始化原生存储，也不得以非空断言绕过实际内存安全检查。固定布局中 optional 的存储表示不能据此擅自改变源码对属性存在性的观察；不再把“省略必定等同显式 undefined”作为所有源程序的通用规则。

### 5.2 类型工具、联合与闭包

interface、条件类型、映射类型和泛型复用官方编译期分析，不产生运行时 interface 对象。泛型按具体类型实参全程序特化、复用相同实例；普通递归允许，无限增长或超过显式编译预算则诊断拒绝，不回退运行时泛型。原生 ABI 不暴露未特化泛型。

联合按 TS 检查和收窄；运行时表示须为静态可确定的类型化表示，架构要求的显式标签联合不等于一般动态值。不把存储标签要求扩大为所有源码联合必须手写判别字段；实际 ABI 布局及值/引用分类随消费者核验，不引入隐式装箱。

闭包捕获逻辑绑定，共享可变绑定的写入可见，必要时提升到受管环境而非保留失效栈地址；值捕获优化须证明无可观察差异。逃逸闭包不能携带逃逸借用，闭包保存 FunctionId 而非持久代码地址。

### 5.3 模块与异常

沿用官方模块判定、解析与初始化行为；首批只覆盖单模块。值导入环、动态导入等若当前未接入应列待实现，不预先永久禁止值循环，也不把“顶层无任何宿主效果”规定为普通 TS 源码规则。宿主调用仍受明确能力授权约束。

Runtime 的模块初始化失败不发布部分模块状态，当前实例不自动重试；这不承诺回滚外部已发生效果。具体实例状态及重载协议属于对应消费者，不在此重设计普通模块语法。

Managed Exception 沿用普通 throw/catch/finally 行为，不要求单一名义异常基类；[ADR-0012](adr/0012-nominal-managed-exceptions.md) 已停用。架构仍限制异常不跨 Zig ABI、不进入计算内核；trap 与 Execution Abort 保持独立。此处不宣称任意 JS 动态值或其执行支持已经实现。

### 5.4 容器、文本、ABI 与内核

保留架构的连续同构向量 T[]/Array<T>、ReadSpan/Span 借用视图、值/引用平面和 Handle 边界。向量不是 JS 稀疏数组；普通数组共享别名/身份及浅 readonly 沿用既有原则，不引入 move-only、隐式复制或 COW。容器拥有者及回收需正式消费者，不能从普通类的复制/相等直接推出其实现。

2026-09-30 用户接受 R03 Q10：普通 tsfg String 保留既定 TS UTF-16 码元行为和值域，内部 canonical WTF-8 无损保存包括孤立代理码元，不进行 Unicode 文本归一化。StringView 另为严格 UTF-8、字节长度的受控借用；不能严格输出时显式失败，有损转换仅由调用方明确选择。源码编码、字符串值和借用边界分别定义，不用字节长度/切片替代逻辑码元操作；见 [ADR-0019](adr/0019-lossless-strings-strict-utf8-views.md)。

用户同时接受 R03 Q11：活跃 Span Borrow 期间任何别名不得改变所借容器长度/容量、释放或转移缓冲区，按真实最后使用点结束借用；串行已有元素写入可对视图可见，ReadSpan 不等于全局冻结。返回和捕获仍受实际拥有者寿命与静态逃逸证明，未知别名不新增动态兜底；见 [ADR-0020](adr/0020-stable-container-during-span-borrow.md)。

2026-09-30 用户接受 R03 Q12 B：普通密集 Array 下标读取有效元素返回 T，缺失/越界在原生访问前产生结构化语义 trap；T 包含 undefined 时有效元素仍可正常返回 undefined。普通 TS/JS 对缺失索引返回 undefined，本选择是明确必要差异，不由密集存储自动推出。trap 沿用第 6 节请求终止、不进用户 catch/finally、不回滚先前效果及 Runtime 自身清理契约；VM/AOT 保持求值顺序、首个失败与源码锚点，断言不取消安全检查。见 [ADR-0021](adr/0021-checked-native-array-index-read.md) 与 [R03 澄清/验收要求](r03-ir-normalization.md)。

strict 不自动启用 noUncheckedIndexedAccess，Q12 不批准开启该 flag；checked T-read 与官方前端事实/类型映射须在正式规范中协调，本轮未实现。用户同时接受 Q13 A：合法动态覆写、恰好末尾追加和缩短可支持，静态已知制造 gap/holes 或未初始化增长的非法形式编译期拒绝；受支持动态操作违反密集/已初始化不变量及 Span/ReadSpan 越界时，在非法访问/修改前结构化语义 trap，沿用第 6 节请求终止契约。动态检查不放宽 Q6/Q11 的静态安全要求：活跃 Span 借用期间禁止追加/缩短，即使容量足够。GPU 失败协议按独立领域契约落实，不能套用普通请求 trap。取舍与验收见 [ADR-0022](adr/0022-dynamic-dense-container-boundaries.md) 和 [R03](r03-ir-normalization.md)。可选查询接口名称及签名仍未批准。

Zig 不持有受管裸指针；仅显式 ABI 安全类型跨边界，GC 对象使用 Handle。内核禁止受管分配、GC 引用、异常、await、锁及逃逸借用；Query/Job 的效果与访问集合由编译器分析。CPU/GPU 的独立数值和并行契约随 W4/W5 确定，不偷换成普通 TS/严格双后端契约。

## 6. 失败与后端无关预算

trap 终止本次执行请求，返回结构化失败，不杀宿主、不由语言 catch 捕获、不自动回滚先前效果。首批观察返回值或首个 Trap Code 及源码锚点；有状态/宿主能力接入时补充可观察效果。

Semantic Fuel 与活动调用深度由 VM/AOT 共用：

- 函数入口及每次 while 条件求值前各耗 1 fuel，包含首次和最终为假的检查。
- 余额不足时在该事件前 trap；先求值实参，再进入被调函数。
- 入口活动调用深度为 1，超过上限时在进入新帧前拒绝。
- 优化、内联必须保留逻辑计费事件，不能按各后端物理指令数改变失败位置。

物理指令、内存及宿主时限分别受限；物理时限/内存耗尽为 Execution Abort，不能冒充语义 trap 或符合 oracle 的成功。背景见 [ADR-0010](adr/0010-backend-independent-semantic-budget.md)。

预算默认值、同事件超限优先级等在消费它的执行契约中固定并随 fixture 记录，不依赖宿主隐含值；这是后续 spec/实现必须补齐的工程契约，不是继续遍历语言问答的理由。

2026-09-30 用户接受 R03 Q7，补齐异常与预算交汇规则：Managed Exception 按 TS 执行 catch/finally；语义 trap（含 Fuel/深度耗尽）和 Execution Abort 终止请求，不进入语言 catch，也不继续执行用户 finally。Runtime 必须清理自身必要的帧、GC 根、借用及宿主边界资源，该清理不运行用户回调，不承诺回滚先前效果。R03 显式保留这些不同通道，R05/R06 联合验证执行、清理与宿主存活；见 [ADR-0017](adr/0017-request-termination-skips-user-finally.md)。

## 7. Conformance Corpus 与诊断

Semantic Oracle 独立于被测实现，来源可以是固定上游规则/测试的适用预期、明确数学规则或人工可核验的 tsfg 差异预期。VM/AOT 一致只是附加证据，不能排除共享 lowering 错误；不从当前编译器结果倒灌唯一正确答案，不以 JS 执行结果覆盖 tsfg 差异，也不创建第二套完整参考解释器。

- 每个用例关联稳定 Language Rule、能力要求、目标/模式、类型化输入与 oracle。沿用规则追溯上游基线，必要差异追溯当前契约。
- 规则使用 Rule ID；Diagnostic Code 和 Trap Code 独立分配，可与规则多对多关联，删除不复用。成功规则不虚构错误码。
- 诊断包含阶段、严重性、错误码、规则关联及主源码位置；主要诊断和结构化字段是机器契约，完整文案及全部级联诊断不是。
- 源文件 UTF-8，位置使用原始解码文本的 UTF-16 code-unit 半开区间，行列从 0 开始，保留原始换行/转义。按相对逻辑文件名、起点、错误码确定排序，不依赖宿主绝对路径或文案。
- .ts 源码与版本化 JSON 用例记录分离。整数为类型加十进制字符串，bool 为 JSON boolean，浮点为类型加定宽十六进制原始位；记录层保留非规范 NaN 以验证搬运/位重解释。
- Case ID 稳定且不复用；预期修改区分规范变更和用例修正，运行结果单独保存，不能自动覆盖 oracle。
- 区分规范已定、实现待接入、通过、失败；当前支持范围内每条适用 MUST/MUST NOT 有可追溯的适用正反例和边界预期。没有非法形式的成功规则记录适用性，不虚构负例。

具体 ID 拼写、JSON 字段、同位诊断次级排序和覆盖校验入口在 to-spec/相应实施中据上述约束固化，无需再问用户一般 TS 行为。语料格式不冒充 R04 产品制品契约；本次没有创建 runner、fixtures 或运行新的语言验收。
